## Implementation contract

`fsref_ipc.cpp` has three distinct boundaries: emitter returns raw own references;
comparator independently creates an expected reference and compares one exactly
80-byte input; an instrumented own producer performs actual Carbon fork calls,
allocation, read, vector copy and normal release. Its model23-byte resource is
not an Adobe PiPL. MacErrors.h identifies errFSRefsDifferent as-1420.

`fsref_ipc.py` binds build/source/binary/payload, execs each IPC process and validates
the exact same/different result; unrelated failures cannot pass a negative control.
The Chain validator separates nested invocations even if an allocation address
is reused. Counts remain64-bit; fork reference is a Carbon token, not a POSIX fd.

`fsref_debug.py` admits only its own newly built executable beneath the private
build directory. It reuses existing stop classification, identity, bounded borrow
and detach. Typed local FSRef/fork/size/read-output spans have explicit source
initialization/lifetime contracts. Reads of copied payload require a matching A
reference and successful full read. B's payload is not read by the debugger.
The negative replay changes one event of the real captured journal; it is a
validator test, not a second naturally executed failure in the native process.

The own NOP probe is instrumented after the normal API result. It does not prove
that ASL+0x28630 has the same stack layout, initialization, reentrant pairing or
unwind coverage. Neither this helper nor FSRef IPC proves an Adobe copy interval,
startup writer→public installed key, render dependencies or safe late append.
Unknown debugger outcomes preserve the owned process/debugger for attention;
there is no automatic kill. Existing collectors/profiles remain unchanged.
