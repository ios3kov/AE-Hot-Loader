1. RIN-001: exact token, executable and module gate before any SDK access; entry
   stays inert outside its prospective host. A request binds compiled run/source/
   build, current PID/start and final binary hash, with explicit read-only review.
2. RIN-002: derive measured scope from the actual loaded self and pinned MEE: file
   SHA, loaded header/text/export and UUID/data-root checks. Never accept a root
   from the request or simply echo its binary hash without loaded self validation.
3. RIN-003: rebind scope and image inventory immediately around one bounded
   capture. Changed identity/images or binding exceptions refuse decoded names,
   preserve completed copy frames and consume the attempt without retry.
4. RIN-004: connect the existing guarded transaction and five-file disk journal;
   retain safe public SDK project/registry pre/postflight, main-thread requirement,
   fixed 15-second transaction deadline and provisional producer evidence.
5. RIN-005: compile/sign/hash exact clean source; validate exports, identity and
   native inert entry behavior. No Adobe library loading into the build process,
   installation, AE launch or modification of an existing helper.
6. RIN-006: owned-data regression covers scope/image change and exception boundaries
   with real bounded capture; review source/API/SDK provenance and run clean local
   regression plus both CI workflows at the actual code SHA.

## Trust and remaining gate

This candidate is preparation only. No live consent is granted by config validity
or request syntax. The consumed earlier observe-d548b007e316 approval does not
cover this helper. External request publication and independently timed validation
are not connected in this stage. Before a live request, the supervisor must derive
expected MEE root from verified image/header plus reviewed static layout, rather
than trusting the producer root, and use a clock started before publication. The
core timer begins after initial binding; it alone does not bound the whole run.
The whole-journal verifier still reports `host_execution_verified=false`.

Point-in-time loaded-image/root checks and matching copies do not establish a
lifetime lease, atomicity, private ABI safety, late registration or release readiness.
